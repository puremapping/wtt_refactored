#### B. 文件下载 API ✅ 已验证打通

```
GET https://data.beijing.gov.cn/cms/web/bjdata/api/userApply.jsp
    ?id=<文件编号>
    &key=<个人唯一标识码>

返回：{
  "reason": "请求成功!",
  "code": "0",
  "result": {
    "address": "https://data.beijing.gov.cn/docs/2026-01/xxx.csv",
    "update_date": "2026-01-20 10:30:00",
    "name": "市文化和旅游局-北京市等级景区信息数据",
    "id": "0265524c802846b29fa4132aa12a12f1"
  }
}
```

**⚠️ 关键坑：文件编号 ≠ 资源 ID**

- 数据集详情页（`/zyml/ajg/slyw/19605.htm`）里的 `downloadResource/<32位hash>` 是 **resourceId**
- `userApply.jsp` 要的是 **文件编号 = 32位 hash + 5位内容ID**，共 37 位
- 传 32 位 → `{"reason":"请输入正确的文件编号！","code":"3"}`
- 传 37 位（即使后缀随意）→ 成功

**正确的文件编号来源**：`dataDoc.jsp` 说明文档页的表格，HTML 结构为：
```html
<tr>
  <td>市文化和旅游局-北京市等级景区信息</td>
  <td>csv</td>
  <td>2026-01-20</td>
  <td>0265524c802846b29fa4132aa12a12f186307</td>   <!-- 这才是文件编号 -->
</tr>
```

**实测样例（北京市等级景区信息）：**

| 格式 | 文件编号 |
| --- | --- |
| csv | `0265524c802846b29fa4132aa12a12f186307` |
| rdf | `15eede45d4d4458b91fe47657dbbad5886307` |
| xlsx | `333ec11c44a4408e948f694160fa1f4386307` |

**key 错误码对照（实测）：**
- 无 key → `{"reason":"请输入唯一标识码！","code":"2"}`
- 格式错误 → `{"reason":"不是合法Key的请求!","code":"1"}`
- 编号长度不足 → `{"reason":"请输入正确的文件编号！","code":"3"}`
- 正常 → `{"reason":"请求成功!","code":"0"}`

### 1.6 注册门槛 ✅ 已解决，但 key 有时效性 ⚠️

平台原文：

> "本网站提供两种方式获取数据资源：下载数据、在线调用API。您如果想通过本网站下载数据、在线调用API，**请先注册，只有成为本网站注册用户后，才可以获取相应的资源服务**。"

登录页：https://data.beijing.gov.cn/cms/web/bjdata/sso/ssoLogin.jsp

**已获取有效 `key`，全部 API 打通。但实测发现 key 会滚动失效：**

| key | 生成时间 | 调用结果 |
| --- | --- | --- |
| `<KEY>（滚动值，已失效）` | 19:10:44 | ✅ 请求成功 |
| 同一个值 | 19:17 | ❌ `不是合法Key的请求!` |
| `<KEY>` | 19:17:54 | ✅ 请求成功 |

**行为：** 每次打开个人中心的「我的唯一码」页面（`https://data.beijing.gov.cn/grzx/wdwym/index.htm`）都会生成**新 key**，**旧值立即作废**。存活窗口实测约 5-10 分钟。

**对开发的影响：**
- key **不能**静态写进配置长期使用
- 需实时获取，或在一次会话内完成全部下载
- `code:1 不是合法Key的请求!` 有两种原因（值错 / 已过期），**先重新拉 key 再排查其他**，不要误判为账号问题
- 列表 API（`/cms/web/search`）不依赖 key，可用来区分"平台挂了"还是"只有 key 过期"

**凭证管理：** 已抽到 `.env` 的 `BJ_OPEN_DATA_KEY`，脚本从环境变量读取；`.env` 已加入 `.gitignore`。

## 四、和风天气 API ⚠️ 方案过时

### 4.1 实测结果

| 检查项 | 结果 |
| --- | --- |
| `devapi.qweather.com` | HTTP **202** |
| `api.qweather.com` | HTTP **202** |
| 裸调 `/v7/weather/now` | `{"error":{"status":403,"title":"Invalid Host"}}` |

### 4.2 根本原因（官方文档确认）

> "对于每个开发者帐号来说，**API Host 都是独立、唯一的**，同时 API Host 也是身份认证的一部分"
>
> "警告：如果是使用的是原公共 API 地址，例如 api.qweather.com、devapi.qweather.com 或 geoapi.qweather.com，请尽快更换为你自己的 API Host…**原公共 API 地址将从 2026 年起逐步停止服务**。"

账号专属 Host 形如：`h2a9cf3mhs.xy.qweatherapi.com`（控制台-设置中查看）

### 4.3 认证方式已变更

和风现在使用 **JWT (EdDSA / Ed25519)**，不再是简单 API Key：

```python
import jwt, time
payload = {
    'iss': 'YOUR_DEVELOPER_ID',
    'sub': 'YOUR_PROJECT_ID',
    'iat': int(time.time()) - 30,
    'exp': int(time.time()) + 900,   # 15 分钟有效期
}
headers = {'kid': 'YOUR_KEY_ID'}
encoded_jwt = jwt.encode(payload, private_key, algorithm='EdDSA', headers=headers)
```

需要四样凭证：`DEVELOPER_ID`、`PROJECT_ID`、`KEY_ID`、`PRIVATE_KEY`。

**影响：** PRD 第 4.2 节把和风列为"实时天气 API"过于简化，实际接入成本高于预期（JWT 签发 + 专属 Host）。

## 五、环境问题记录（排查过程）

### 5.1 curl 全体返回 000 的根因

**症状：** 所有 HTTPS 请求返回 `http=000`，疑似网络全断。

**根因：** 本机 curl 是 **Schannel 后端**（非 OpenSSL）：
```
curl 8.21.0 (x86_64-w64-mingw32) libcurl/8.21.0 Schannel
```
Schannel 会主动查询 OCSP 证书吊销列表，在受限网络下查询失败即判定请求失败：
```
schannel: next InitializeSecurityContext failed:
CRYPT_E_REVOCATION_OFFLINE (0x80092013)
```

**修复：** 所有 curl 调用添加 `--ssl-no-revoke`。

**验证：** 加该参数后，`data.beijing.gov.cn` 由 000 变为 **200，耗时 0.095s**。此前所有"连不上"的判定均为误报。

### 5.2 代理出口故障

**症状：** 走代理访问境外站点全部 5 秒超时。

**根因：** 订阅「仙路湾_包月」当前节点走 `xl1` 入口，该入口整台服务器不可达。

| 入口 | 地址 | TCP 连通 |
| --- | --- | --- |
| xl1.xlw1.cc.cd | 128.108.221.140 | ❌ 5/5 端口全 FAIL |
| xl2.xlw1.cc.cd | 202.85.53.215 | ✅ 5/5 端口全 OK（美国-2 最快 128ms） |

**修复：** 切换节点至 xl2 入口（美国-2 / 香港-2 / 新加坡-2 等）。
