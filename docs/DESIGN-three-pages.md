# 三页式产品设计

**日期：** 2026-10-21
**定位：** 从「单一对话入口」升级为「内容社区 + AI 助手 + 个人空间」三段式产品
**现状：** 目前只有 1 个主页面（对话）+ 1 个管理后台，无内容、无个人主页

---

## 一、全局结构

```
┌──────────────────────────────────────────────────────────┐
│  顶栏（全局常驻）                                          │
│  [Logo]  [搜索框 ────────]  [AI]     [消息] [头像]        │
├──────────────────────────────────────────────────────────┤
│                                                          │
│   ①浏览页  /        ②AI 对话页  /chat     ③个人主页  /me  │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**三块以「底部/顶栏导航」切换，不互相跳转丢失状态。**

| 页 | 路径 | 核心问题 | 回答的是 |
|---|---|---|---|
| ① 浏览页 | `/` | 「有什么好玩的」 | **发现** |
| ② AI 对话页 | `/chat` | 「我该怎么玩」 | **决策** |
| ③ 个人主页 | `/me` | 「我玩过什么」 | **沉淀** |

## 二、① 浏览页（`/`）

### 2.1 布局

```
┌──────────────────────────────────────────────────────────┐
│  [Logo]  [搜索北京/成都…    ] [AI]      [消息] [头像]    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│   ┌─────────────┬─────────────┬─────────────┐            │
│   │  内容        │  旅游灵感    │  今日热榜    │  ← 三个页签 │
│   └─────────────┴─────────────┴─────────────┘            │
│                                                          │
│   ┌────────┐ ┌────────┐ ┌────────┐                       │
│   │ 图     │ │ 图     │ │ 图     │      ← 瀑布流          │
│   │ 标题   │ │ 标题   │ │ 标题   │                        │
│   │ 作者❤️ │ │ 作者❤️ │ │ 作者❤️ │                        │
│   ├────────┤ └────────┘ ├────────┤                       │
│   │        │ ┌────────┐ │        │                       │
│   └────────┘ │        │ └────────┘                       │
│              └────────┘                                  │
└──────────────────────────────────────────────────────────┘
```

### 2.2 三个页签

| 页签 | 内容来源 | 排序 | 说明 |
|---|---|---|---|
| **内容** | 全部帖子 | 推荐/最新 | 默认页签，瀑布流 |
| **旅游灵感** | **用户分享的行程** | 按分享时间 | **从 AI 推荐窗口一键分享出来**，结构化的行程卡片 |
| **今日热榜** | 全站 | 按热度 | 今日最多浏览/收藏的帖子 |

**「内容」和「旅游灵感」的区别：**

- **内容**：普通图文帖（小红书式），自由形式
- **旅游灵感**：**AI 生成的行程**，带结构（几站、时长、路线），可点开看完整安排

### 2.3 帖子卡片

**普通内容帖：**

```
┌─────────────────┐
│                 │
│      图片        │  ← 封面图，高度不定（瀑布流）
│                 │
├─────────────────┤
│ 标题最多两行...   │
│ @作者  ❤️ 128    │
└─────────────────┘
```

**旅游灵感帖（行程分享）：**

```
┌─────────────────────────┐
│  成都一日 · 慢生活        │
│  ┌───┬───┬───┬───┐      │  ← 多图拼贴
│  └───┴───┴───┴───┘      │
│  📍 4 站 · 8 小时 · 12km │  ← 结构化摘要
│  「想歇一歇，找个人少的」  │  ← 动机（来自 AI 对话）
│  @作者  ❤️ 89  [复制行程] │
└─────────────────────────┘
```

**关键：** 行程分享带**动机标签**（「想歇一歇」），这是本产品独有的 —— 用户可以按「我现在也想要这种感觉」来找。

### 2.4 搜索框 + AI 按钮

```
[搜索北京、成都、古镇…        ] [AI]
```

| 元素 | 行为 |
|---|---|
| **搜索框** | 搜帖子 / 地点名；回车出结果页（暂用页签过滤实现） |
| **AI 按钮** | **把搜索词带进对话页**：`/chat?q=<关键词>` |

**AI 按钮的意义：** 搜不到就直接问 AI —— 搜索和对话不是两套系统，是一个入口的两种输出。

## 三、② AI 对话页（`/chat`）

### 3.1 沿用现有实现

**现有的对话页（左对话 + 右画像 + 右行程）直接搬过来**，只做导航调整。

### 3.2 新增：一键分享到「旅游灵感」

**行程生成后，结果区下方加一个按钮：**

```
┌────────────────────────────┐
│  ...行程内容...             │
├────────────────────────────┤
│  [✏️ 继续修改]  [📤 分享行程] │
└────────────────────────────┘
```

**点击「分享行程」→ 弹窗：**

```
┌──────────────────────────────┐
│  分享你的行程                  │
│                              │
│  标题  [成都一日 · 慢生活   ]  │
│                              │
│  封面  [选择图片 / 上传]       │
│                              │
│  说两句 [想歇一歇，找个人少的   │
│         地方待了一天...      ] │
│                              │
│  ☑ 附带完整行程（4 站 · 8 小时）│
│  ☑ 公开（其他人能看到）        │
│                              │
│          [取消]  [发布]       │
└──────────────────────────────┘
```

**发布后：** 出现在浏览页的「旅游灵感」页签，也出现在个人主页的「旅游回忆」。

### 3.3 从浏览页带词进来

`/chat?q=成都` → 对话页自动把「成都」填进输入框（**不自动发送**，让用户自己补全意图）。

### 4.2 三个入口

| 入口 | 内容 | 现状 |
|---|---|---|
| **⚙️ 设置** | 昵称、头像、城市、隐私 | 无，要新建 |
| **💬 消息** | 赞/评论/AI 通知 | 无，要新建 |
| **🗺️ 旅游回忆** | **完成的行程记录** | 部分有（`sessions.itinerary`），要整理 |

### 4.3 旅游回忆（重点）

**你说的「AI 全程伴游后一键总结」是这个模块的核心。**

**分两个阶段：**

| 阶段 | 内容 | 数据来源 |
|---|---|---|
| **现在能做** | 列已有行程 + 生成一句话总结 | `sessions` 表里的 itinerary |
| **将来**（有伴游后） | 实际去了哪、花了多久、心情、照片 | 需要「伴游」数据（未实现） |

**建议先做「现在能做」的部分** —— 用户点「生成回忆」，AI 把行程 + 对话里的画像生成一段叙述，配地图，形成可分享的回忆卡片。

## 五、数据模型（新增）

**现有表：** `attractions` / `transport` / `crowd_index` / `users` / `sessions` / `events`

### 5.1 新增 `posts`（帖子）

```sql
CREATE TABLE posts (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     TEXT NOT NULL,           -- 作者
    type        TEXT NOT NULL,           -- 'content' | 'inspiration'
    title       TEXT NOT NULL,
    body        TEXT,                    -- 正文（content 类型用）
    cover_url   TEXT,                    -- 封面图
    images      TEXT,                    -- JSON 数组，多图
    -- 旅游灵感专用
    itinerary   TEXT,                    -- JSON，完整行程（来自 sessions）
    motivation  TEXT,                    -- 动机标签（「想歇一歇」）
    stops_count INTEGER,
    hours       INTEGER,
    -- 排序与统计
    likes       INTEGER DEFAULT 0,
    views       INTEGER DEFAULT 0,
    is_public   INTEGER DEFAULT 1,
    created_at  TEXT NOT NULL,
    deleted_at  TEXT
);
```

### 5.2 新增 `likes` / `comments`

```sql
CREATE TABLE likes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id    INTEGER NOT NULL,
    user_id    TEXT NOT NULL,
    created_at TEXT NOT NULL,
    UNIQUE(post_id, user_id)
);

CREATE TABLE comments (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id    INTEGER NOT NULL,
    user_id    TEXT NOT NULL,
    content    TEXT NOT NULL,
    created_at TEXT NOT NULL,
    deleted_at TEXT
);
```

### 5.3 新增 `messages`（站内通知）

```sql
CREATE TABLE messages (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    TEXT NOT NULL,           -- 收件人
    type       TEXT NOT NULL,           -- 'like' | 'comment' | 'ai' | 'system'
    ref_id     INTEGER,                 -- 关联的 post_id 等
    content    TEXT NOT NULL,
    is_read    INTEGER DEFAULT 0,
    created_at TEXT NOT NULL
);
```

### 5.4 扩展 `users`

```sql
ALTER TABLE users ADD COLUMN avatar_url TEXT;
ALTER TABLE users ADD COLUMN city TEXT;
ALTER TABLE users ADD COLUMN bio TEXT;
```

## 九、已拍板的决策

| # | 问题 | 决定 | 影响 |
|---|---|---|---|
| 1 | **图片存哪** | **本地** | 存 `data/uploads/`，DB 只记相对路径 |
| 2 | **今日热榜热度** | **搜索热度** | 按该帖被搜索命中的次数排序（不是浏览/点赞） |
| 3 | **要不要评论** | **要** | 需要 `comments` 表 + UI |
| 4 | **回忆总结用不用 LLM** | **用** | 每次生成消耗 token，考虑缓存 |
| 5 | **浏览页对未登录开放** | **开放** | 匿名可浏览，互动需登录 |

**补充决定：**

- **保留 `/chat` 作为默认入口** —— 现有链接不断，浏览页走 `/`（或反之，见实现说明）
- 图片本地存储方案：
  ```
  data/uploads/{user_id}/{uuid}.{ext}
  visits: /uploads/{user_id}/{uuid}.{ext}
  ```
  ⚠️ 需加静态文件路由，且**限制文件类型与大小**（防上传可执行文件）

### 9.1 「搜索热度」的定义

**不是「帖子被搜索命中的次数」这么简单** —— 需要一条记录链：

```
用户搜索「成都」→ 记一条 search_log（关键词、时间、用户）
                 ↓
          匹配到的帖子 → post_impressions（post_id, keyword）
                 ↓
          热榜 = 近 24 小时里被搜索命中的帖子，按命中次数排序
```

**要新增两张表：**

```sql
CREATE TABLE search_logs (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    TEXT,                    -- 可为空（未登录也能搜）
    keyword    TEXT NOT NULL,
    created_at TEXT NOT NULL
);

CREATE TABLE post_search_hits (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id    INTEGER NOT NULL,
    keyword    TEXT NOT NULL,
    created_at TEXT NOT NULL
);
```
